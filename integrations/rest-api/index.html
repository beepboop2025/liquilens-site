Integration · OpenAPI and JSON

Automate the evidence. Keep the as-of date.

The public REST API serves the Failure Radar, institution details, historical-evidence records, RBI actions and bounded context as JSON. The OpenAPI 3.1 document is the machine contract; the payload’s own evidence fields remain authoritative.

Integration rules

Validate the schema

Generate clients from the published OpenAPI document or validate responses directly; do not depend on undocumented page markup.

Store the boundary

Persist the response as-of, evidence status and source references beside any internal annotation.

Fail closed

Timeouts, missing institutions and stale or absent fields remain unavailable. They are never zero, calm or a passing grade.

Authority boundary

The public API is a research interface. It does not grant a credit rating, recommendation, supervisory conclusion, complete-universe guarantee or permission to redistribute third-party data.

Questions from API teams

Does the public LiquiLens REST API require a key?

No. The documented public research routes require no API key.

What should an integration cache?

Cache the exact payload with its as-of fields and source status. Do not cache a derived healthy state when the upstream record is missing or unavailable.
