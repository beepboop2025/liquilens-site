Try a public bank review

Designed for bank, NBFC, co-operative and other financial-institution workflows. Actual evidence coverage and regulatory applicability are specific to the institution and jurisdiction.

A repeatable review

  1. Identify and check coverage. Start with the exact institution, jurisdiction and question. Discover available records before requesting a dossier.
  2. Read the institution evidence. Preserve disclosed deterioration, funding exposure, source periods, missing fields and historical-method limitations.
  3. Add relevant market context. Check Seiche’s source health, funding state and money-market observations. Keep their clocks separate from the institution’s filings.
  4. Leave a reviewable handoff. Export evidence, counterevidence and open questions. Compliance remains unassessed until the applicable rules, private inputs and accountable reviewer are established.

Teach the agent the task

Download the institution-review skill into a folder named liquilens-institution-review. OpenClaw can install that reviewed local folder with:

openclaw skills install ./liquilens-institution-review

For Hermes, place the folder under ~/.hermes/skills/. Keep existing skills. The skill describes relevant financial tasks, entity resolution, tool order, source handling and unassessed compliance; it does not force unrelated agent calls.

Try this prompt after connecting:

Use LiquiLens to discover the covered institutions. For the exact institution I select, review disclosed stress buildup and missing evidence. Add relevant Seiche funding context with its own source dates. Return a sourced review and open questions for our risk team. Keep compliance unassessed.

Run it from a script or automation tool

Download institution_review.py and financial_research.py into the same directory. Python 3.11+ uses the standard library; no LLM or API key is needed.

python3 institution_review.py --bank-slug cosmos-ucb \
  --jurisdiction IN --institution-type urban-cooperative-bank \
  --verification > institution-review.json

# For an exact institution returned by Failure Radar coverage:
python3 institution_review.py --institution EXACT_SLUG_FROM_COVERAGE \
  --jurisdiction YOUR_JURISDICTION --institution-type YOUR_CLASS

--verification labels operator checks separately from adoption. Exit 0 means the expected responses returned; it does not mean fresh data or a safe institution. Exit 2 preserves partial, stale or unavailable evidence. Exit 1 means an invalid request or processing error. The jurisdiction and class are caller labels, not validated regulatory coverage.

For n8n and other schedulers, run the script within your approved environment and branch on the exit code. Keep each source’s returned dates and errors. Choose the watchlist, cadence and destination before scheduling; avoid repeated calls inside a single review. Existing n8n bank-review recipe.

The public REST board is available at /api/failure-radar/board; the served OpenAPI describes available API routes. API access and MCP use the same underlying evidence.

What this workflow establishes

A source-backed research handoff for a human reviewer. Public records can support stress, default-risk and compliance questions, but cannot certify a private book’s live LCR, NSFR, CRR or SLR. Missing coverage, stale sources and disagreements remain visible.

Undertow adds size-dependent market-liquidity evidence when relevant. Lab supplies shared evidence and evaluation contracts. Palimpsest supplies separately governed information-control and China-source context. Their outputs retain their own scope.

Compatibility basis: official OpenClaw and Hermes documentation checked 23 September 2026. Configuration parsing and endpoint checks are distinct from testing an installed client or an LLM’s routing behavior.
