Read a bank filing with Python and preserve its evidence limits

Disclosure: I build LiquiLens. This tutorial uses its public research tools and a disclosed example from Cosmos Co-operative Bank, an Indian urban cooperative bank. It makes no lending or investment recommendation.

A financial-research integration needs more than a successful request. The record should still identify the institution, the filing period, the source and the missing evidence after it reaches your application.

Here's a small Python workflow for that task. It uses an existing standard-library recipe, then adds a short reader for its output. You need Python 3.11 or later. No model or API key is needed for these public examples; service limits apply.

Inspect the recipe first

The downloadable source and its manifest are public:

  • https://liquilens.in/developers/recipes/financial_research.py
  • https://liquilens.in/developers/recipes/manifest.json
  • https://liquilens.in/developers/

Download the script into a directory you control, then inspect it before executing it:

curl --fail --show-error --max-time 30 \
  https://liquilens.in/developers/recipes/financial_research.py \
  -o financial_research.py

The source retrieved on 4 October 2026 declared recipe version 1.1.0 and SHA-256 5ac34083238de25be4fc952464cd7ba09f0735683b32f389f06b9429906be9e6. Check your copy with this portable command:

python3 -c "import hashlib,pathlib; print(hashlib.sha256(pathlib.Path('financial_research.py').read_bytes()).hexdigest())"

A different hash may mean the published script changed. Review the new source and manifest before using it; do not assume the version or behavior below remains current. The recipe limits each HTTP exchange to 20 seconds and 2 MiB, restricts endpoints and does not automatically retry.

Discover coverage before choosing a bank

python3 financial_research.py bank-review --verification > coverage.json
python3 financial_research.py bank-review --slug cosmos-ucb --verification > cosmos-review.json

These commands, when run, call public read-only MCP tools. --verification identifies this operator rehearsal as synthetic traffic. Use it for tests, demos and health checks so those calls can be separated from adoption. Actual users doing their own research can omit that flag.

Without a slug, bank-review requests banking_specialisation_coverage. With a slug, it checks for an exact match in evidence.coverage.rows before requesting bank_asset_quality_review with include_history: true. A plausible-sounding name is not a valid substitute for an exact slug.

Read the returned contract

The source defines this outer structure; fields inside evidence.review come from the public bank record:

FieldMeaning
schemaliquilens.research-recipe.v1
recipebank-review
verificationWhether the operator flag was supplied
outcomeevidence_returned, not_covered or an unavailable result
execution_authorityfalse
retrieved_atWhen this recipe assembled its result
evidence.coverage.rowsExact covered names, slugs and evidence states
evidence.reviewPresent only when a named review was requested and returned

For the Cosmos API record inspected on 4 October, the inner schema was liquilens.bank-specialisation.v1, its status was observed, and period_end was 2026-03-31. available_at and the inner retrieved_at were 2026-09-05T07:05:33Z; publication_date was null. These are separate clocks. The example does not establish when that filing first became public or whether a newer filing exists.

The record's npa_movement keeps reported upgrades, cash recoveries and write-offs separate. Its regulatory_comparison.status was scope_unverified. Preserve those fields when summarizing; do not translate a missing regulatory comparison into a conclusion that no restrictions apply.

Inspect the current API record directly at https://api.liquilens.in/api/experimental/v1/banking/institutions/cosmos-ucb?include_history=true .

Add a small local reader

Save the following original example as read_review.py. It reads a saved response; it does not make network calls or change the source payload.

import json
import sys
from pathlib import Path

payload = json.loads(Path(sys.argv[1]).read_text())
if payload.get("schema") != "liquilens.research-recipe.v1":
    raise SystemExit("Unexpected recipe contract; inspect the saved response.")
if payload.get("outcome") != "evidence_returned":
    raise SystemExit("No review available: " + str(payload.get("outcome")))
review = payload.get("evidence", {}).get("review")
if not isinstance(review, dict):
    raise SystemExit("Coverage returned; choose an exact covered bank slug.")
if review.get("schema") != "liquilens.bank-specialisation.v1":
    raise SystemExit("Unexpected bank contract; inspect the saved response.")
state = review.get("status")
if state not in {"observed", "stale", "historical"}:
    raise SystemExit("Review is unavailable or has an unknown evidence state.")
if state != "observed":
    print("Review limit:", state, "record; do not describe it as current.")
for key in ("name", "period_end", "available_at", "publication_date"):
    value = review.get(key)
    print(f"{key}: {value if value is not None else 'not supplied'}")
print("Evidence state:", state)
for source in review.get("sources", []):
    print("Source:", source)
for limit in review.get("interpretation_limits", []):
    print("Limit:", limit)

Then run:

python3 read_review.py cosmos-review.json

Keep the original JSON alongside any derived display. observed is the record's evidence state, not a freshness guarantee for your particular use. Read its period, available date, comparability notes and source trail before deciding whether it is adequate.

Handle missing evidence and errors separately

The recipe exits 0 when evidence is returned, including stale or historical facts; 2 when the requested result is unavailable or not covered; and 1 for transport, protocol or tool failure. Check the exit code before parsing a redirected file. Errors are written as JSON to stderr, so stdout may be empty after failure.

For 2, show the coverage or unavailability reason and let the researcher choose a supported question. For 1, retain the diagnostic and avoid treating an empty response as a financial finding. The recipe does not schedule work or retry an outstanding request.

Keep missing disclosures as missing. Do not replace them with a model guess. In particular, a falling NPA ratio does not tell you how much cash was recovered, and arithmetic agreement does not authenticate a filing.
